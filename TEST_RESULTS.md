**Passed 60 · Failed 0 · Errors 0 · Skipped 0.**
JUnit: `tests/results/acceptance.xml`.

Окружение: Windows, Python 3.12, PostgreSQL 17.11, закреплённые зависимости
из requirements. Изолированная БД `arcana_test` на loopback-порту 55432;
только синтетические данные. Временный PostgreSQL скачан в `.work/`,
без установки системной службы. После проверки сервер остановлен.

Проверки используют настоящие SQLAlchemy/asyncpg, миграции, транзакции,
unique/check/composite FK, блокировки, очередь и агрегаты PostgreSQL.
`test_backup.py` действительно запускает pg_dump и pg_restore, после чего
применяет актуальный внешний реестр удалений. Telegram-отправки заменены
FakeBot, генерация — FakeLLM; HTTP-поведение LLM отдельно проверено через
httpx.MockTransport, включая тело запросов, ошибки, JSON и параллелизм.

Нагрузочный тест создаёт 100 профилей и выполняет 50 действий с дневником
и историей, пачками по 10. p95 56.5 мс относится только к этому локальному
пути БД, а не к настоящей генерации ИИ или сетевой доставке Telegram.

Дополнительно: compileall без ошибок; pip check без конфликтов; прочитана
структура Compose (app + db + persistent volume); проверены 78 записей
справочника и 79 JPEG, максимальный размер 241546 байт.

Первый полный прогон обнаружил ошибку изменения вложенного списка интересов
в JSON-состоянии онбординга: исправлено копированием состояния перед изменением.
Ошибка в тестовой выборке заметок (текст длиннее разрешённых 2000 символов)
также исправлена. После этого весь набор прошёл. При self-audit добавлены
контракт внутреннего API и проверка полного месячного результата; итоговый
полный прогон включает их.

Живые Telegram/LLM, контейнерный запуск и рабочее расписание backup не
проверялись: токенов/API-ресурсов и Docker нет. Эти ограничения явно отражены
